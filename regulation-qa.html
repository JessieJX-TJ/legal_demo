📖 User guide
Feature overview

AI Regulation Agent is built for automotive regulatory intelligence and offers 3 work modes:

📌 Regulation report generation
Automatically crawls the latest regulations/standards from CATARC, MIIT, SAMR, and other sources, then aggregates structured analysis reports (key regulations / meetings / standard notices / drafting updates).
🌐 Overseas intelligence parsing
Upload overseas regulation/policy PDFs; AI identifies each discrete regulation/standard/consultation and generates the same 4-section analysis structure as Chinese reports.
🧠 Skill configuration
Tune M1 passenger-car pre-filter keywords, add few-shot positive/negative examples, and configure LLM prompt rules; support "dry-run on historical data" for effect checks. All changes are written to an auditable log.
  1. The left "Data source status" shows crawled regulation sources. Click an item to crawl it alone, or click "Crawl all" to pull everything.
  2. Choose a time range (custom / last 15 days / 1 month / 3 months) → click Generate report → async generation → auto-jump to preview
  3. Overseas intelligence: drag a PDF into the dashed box or click "Select PDF" → click Generate report → backend parsing + LLM itemization
  4. Each regulation in the report can expand to: Key points / Policy interpretation / Enterprise actions / Peer references
  5. Skill configuration: after changing keywords/rules, click Save; use the "Dry run" button in PATCH 04 to validate on historical data

Skill configuration details

Skill configuration tells the AI what counts as an "M1 passenger car"—every newly crawled regulation passes this gate before entering a report. If this gate is wrong, later accuracy does not help.

The UI has 4 PATCH panels

  • PATCH 01 · Filter keywords — two tag groups: M1 feature terms (hit = keep) and exclusion terms (hit = drop). Type a term and press Enter to add; click ✕ to remove. Click Save at the bottom; changes apply on the next filter run.
  • PATCH 02 · Few-shot samples — left/right columns for positives (should be M1) and negatives (should not). Samples are appended to the LLM prompt and directly affect is_m1. Prefer 5–10 typical examples per class with clear rationales.
  • PATCH 03 · LLM prompt rules — extra rules in the textarea (e.g. "prioritize safety + intelligent driving") append to the system prompt; the peer blacklist hides in-house brands (SAIC family: IM / Rising / MG / Roewe, etc.) from Peer references.
  • PATCH 04 · Preview & history — non-persistent dry-run area. "Dry run" executes the current skill on the last N days of MongoDB data, showing pass/block counts and diffs vs default (X newly kept / Y newly dropped). Below is change history: who, when, and what.

Suggested tuning workflow

  1. In PATCH 04, click "Dry run" to see the default filter baseline
  2. In PATCH 01, change keywords (e.g. add "intelligent driving" to M1, or "commercial vehicle" to exclusions), do not Save yet
  3. Run "Dry run" again in PATCH 04 and compare the Diff numbers
  4. If the Diff looks right → click Save at the bottom of PATCH 01 → takes effect immediately
  5. To undo → click Restore defaults (top-right) to factory settings (note: few-shot samples are kept)
💡 Operator field · The Operator box (top-right) is written into every audit log. Set your name (e.g. zhangsan) so history shows who changed what. Default is im, stored in localStorage across reloads.
