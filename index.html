📖 User guide
Feature overview

AI Legal Agent is designed for automotive regulatory intelligence scenarios and provides 3 work modes:

📌 Regulation report generation
Automatically crawl the latest regulations/standards from sources such as CATARC, MIIT, and SAMR, then aggregate them into structured analysis reports (key regulations / meetings / standard notices / drafting updates).
🌐 Overseas news analysis
Upload overseas regulation/policy PDFs; AI automatically identifies each independent regulation/standard/consultation and generates a 4-section analysis matching the Chinese report structure.
🧠 Skill configuration
Tune M1 passenger-vehicle pre-filter keywords, add few-shot positive/negative examples, and configure LLM prompt rules; support "dry-run on historical data" to preview impact; all changes are written to an audit log for traceability.
  1. The left "Data source status" shows crawled regulation sources; click an item to crawl it alone, or click "Crawl all" to pull everything at once
  2. Select a time range (custom / last 15 days / 1 month / 3 months) → click Generate report → async generation → auto-jump to preview
  3. Overseas news: drag a PDF into the dashed box or click "Select PDF" → click Generate report → backend parsing + per-item LLM recognition
  4. In the report, expand each regulation to view: Key points / Policy interpretation / Enterprise response / Peer reference
  5. Skill configuration: after changing keywords / rules, click Save; to preview impact, use the "Dry-run" button in PATCH 04 against historical data

Skill configuration details

Skill configuration tells the AI "what counts as an M1 passenger vehicle" — every newly crawled regulation passes this gate before it can enter a report. If this gate is wrong, later accuracy does not help.

The UI has 4 PATCH panels

  • PATCH 01 · Filter keywords — two tag groups: M1 feature terms (hit = keep) and exclusion terms (hit = drop). Type a term in the input and press Enter to add; click ✕ after a term to remove it. Remember to click "Save" at the bottom; changes apply to the next filter run immediately.
  • PATCH 02 · Few-shot samples — left/right columns for positive examples (should be M1) and negative examples (should be non-M1). These samples are appended to the LLM prompt and directly affect the is_m1 decision. Aim for 5–10 typical samples per class with clear reasons so the LLM learns faster.
  • PATCH 03 · LLM prompt rules — extra-rules textarea (e.g. "prioritize safety + intelligent driving") is appended to the end of the LLM system prompt; the peer blacklist hides in-house brands (SAIC group: IM / Rising / MG / Roewe, etc.) from the "Peer reference" module.
  • PATCH 04 · Preview & history — a non-persisting dry-run area. Click "Dry-run" to run the current skill on the last N days of MongoDB data, showing pass/block counts and differences vs. the "default config" (X newly kept / Y newly dropped). Below is the change history: who changed what and when.

Suggested tuning workflow

  1. First click "Dry-run" in PATCH 04 to see the current default filter effect (baseline)
  2. In PATCH 01, change a set of keywords (e.g. add "intelligent driving" to M1, or "commercial vehicle" to exclusions), do not click Save yet
  3. Click "Dry-run" in PATCH 04 again and compare the "difference" numbers before and after
  4. If the difference looks right → click "Save" at the bottom of PATCH 01 → takes effect immediately
  5. To undo → click "Restore defaults" in the top-right to reset factory settings (note: positive/negative samples are not cleared)
💡 Operator field · The "Operator" input at the top-right is written into every audit log. Change it to your name (e.g. zhangsan) before editing so the change history can show who made each change. The default is im; it is stored in browser localStorage and persists across reloads.
