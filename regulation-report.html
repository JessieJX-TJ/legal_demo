📖 User Guide
Feature overview

AI Regulation Agent is designed for automotive regulation intelligence scenarios and provides 3 working modes:

Guides the mode you are currently in (Regulation Report / Foreign Intelligence)

📌 Regulation report generation
Automatically crawl latest regulations/standards from CATARC, MIIT, SAMR and other sources, then aggregate into a structured analysis report (key regulations / meetings / standard announcements / under-development updates).
🌐 Foreign intelligence analysis
Upload foreign regulation/policy PDFs; AI identifies independent regulations/standards/consultations item by item and generates a 4-section analysis with the same structure as the domestic report.
🧠 Skill settings
Tune M1 passenger-car pre-filter keywords, add few-shot positive/negative examples, and configure LLM prompt rules; dry-run on historical data to preview effects; all changes are written to an audit log.
  1. In the chat area, select data sources first, click Crawl Data, review crawl results, then set parameters
  2. Set the date range and title → click Confirm Parameters → Generate Report → async generation → preview in chat
  3. Foreign intelligence: drag PDFs into the dashed box or click "Select PDF" → click Generate Report → backend parsing + LLM item-by-item recognition
  4. Each regulation in the report can expand to show: Key points / Policy interpretation / Enterprise response suggestions / Peer reference
  5. Skill settings: after changing keywords / rules, click Save; to preview effects, use the "Dry-run" button in PATCH 04 on historical data

Skill settings details

Skill settings tell the AI what counts as an M1 passenger car — every newly crawled regulation must pass this gate before it can enter the report. If this gate is wrong, later accuracy does not help.

The UI has 4 PATCH panels

  • PATCH 01 · Filter keywords — Two tag groups: M1 feature words (hit = keep) and exclude words (hit = discard). Type a word and press Enter to add; click ✕ on a tag to delete. Remember to click Save at the bottom; changes take effect on the next filter run.
  • PATCH 02 · Few-shot samples — Left/right columns for positive examples (should be M1) and negative examples (should be non-M1). These samples are injected into the LLM prompt and directly affect is_m1 decisions. Aim for 5–10 typical samples per class with clear reasons so the LLM learns faster.
  • PATCH 03 · LLM prompt rules — Extra rules textarea (e.g. "prioritize safety + intelligent driving") is appended to the end of the LLM system prompt; the peer blacklist hides your own brands (SAIC group: IM / Rising / MG / Roewe, etc.) from the Peer Reference module.
  • PATCH 04 · Preview & history — Non-persistent dry-run area. Click Dry-run to run the current skill on the last N days of MongoDB data, showing pass/block counts and differences vs the default configuration (newly kept X / newly dropped Y). Below is the change history — who changed what and when.

Suggested tuning workflow

  1. First click Dry-run in PATCH 04 to see the current default filter effect (baseline)
  2. In PATCH 01, change a set of keywords (e.g. add "intelligent driving" to M1, or "commercial vehicle" to exclude), do not click Save yet
  3. Click Dry-run in PATCH 04 again and compare the Diff numbers before/after
  4. If the diff looks right → click Save at the bottom of PATCH 01 → takes effect immediately
  5. If you regret it → click Reset to defaults at the top right to restore factory settings (note: positive/negative samples are not cleared)
💡 Operator field · The Operator input at the top right is written into every audit log entry. Change it to your name (e.g. zhangsan) before making changes so history can show who edited what. The default is im; it is stored in browser localStorage and persists across reloads.
